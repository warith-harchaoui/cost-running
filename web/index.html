Why cost-running?

Cost models that hide their uncertainty are worse than useless — they give false confidence. cost-running makes uncertainty first-class.

🏷️

Honesty by construction

Every quantity carries a status. A derived value can never claim to be better-founded than its weakest input — the weakest-link rule is enforced at validation time.

📐

Wide-sense dimensions

Money, time, energy, carbon, water — and any extra dimension your team needs. The dimension registry is first-class, not a hard-coded list.

🔬

Real measurement

RAPL counters on Linux give you system-package energy during the run. The tool clearly distinguishes this observed-system figure from a TDP-based estimate — attribution is always stated.

📊

Reports that look superb

Self-contained HTML with inline SVG figures: honesty inventory, status distribution, scenario comparison. Passes the Ralph Eyeball gate before shipping.

🔁

CI drift gate

cost-running diff old.yaml new.yaml flags any dimension that drifted more than 10% (configurable). Exit 1 in CI when the model is out of date.

🔍

Repo audit

cost-running audit . detects languages, archetype, and paid services (OpenAI, Anthropic, AWS, …), then scaffolds a pre-filled cost model with pricing-source URLs ready to complete.

The honesty taxonomy

Every value in a cost model carries one of four statuses. A derived value obeys the weakest-link rule: it can never claim a stronger status than the worst of its inputs.

measured

Measured

Recorded from an actual run on the target system. Wall-clock time is always measured. RAPL-based energy is labelled estimated because system-package attribution ≠ process attribution.

estimated

Estimated

Computed from sourced assumptions or a published formula. Source URL and retrieval date required. Freshness is checked: values older than 90 days earn a provenance warning.

placeholder

Placeholder

A structural stand-in kept visible so the model compiles. Not a real number — the reader should not make decisions from it.

TODO

TODO

A human must supply this value before the model can be trusted. Validation passes but clearly surfaces every TODO so nothing is accidentally left blank.

The near-term workflow

The most valuable path through the tool, in order.

audit
→
measure
→
fill assumptions
→
validate
→
render
→
diff in CI
# 1. Detect languages, archetype, paid services → scaffold model
cost-running audit .  --output cost_of_running.yaml

# 2. Measure a representative run
cost-running measure -- python train.py --grid-gco2e-per-kwh 55

# 3. Fill assumptions, review TODOs in cost_of_running.yaml, then validate
cost-running validate cost_of_running.yaml

# 4. Render a self-contained HTML report (or plain Markdown)
cost-running render cost_of_running.yaml --format html --output report.html

# 5. Gate on drift in CI (exit 1 if any dimension changed > 10%)
cost-running diff cost_of_running.yaml.old cost_of_running.yaml

Install

Runtime install — no system dependency required.

# pip
pip install -r requirements.txt

# conda
conda env create -f environment.yaml
conda activate env-for-cost-running
pip install -r requirements-dev.txt

# Quick start
cost-running init --template full --output cost_of_running.yaml
cost-running validate cost_of_running.yaml
cost-running render cost_of_running.yaml --format html --output report.html
